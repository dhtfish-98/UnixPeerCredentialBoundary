# Threat model and security boundary

The protected operation is an append to an existing root-owned, regular `0600` file. The service process has that access; UID 1000 is the sole authorized local client in the lab; UID 1001 is the adversarial local client. The socket is root-owned `0666` within a root-owned, non-group/non-world-writable directory, so both UIDs can reach the same service. The file is opened with `O_NOFOLLOW`, and its owner/type/mode are checked before the service starts.

The intentionally weak comparison checks only the request's `declared_uid`. A UID 1001 process can write `PUT 1000 ...` and induce a privileged write. The strong build calls `getsockopt(SOL_SOCKET, SO_PEERCRED)` on the accepted connected stream socket and fails closed if the call or credential size is invalid. It requires the kernel UID to equal the configured authorized UID and the declared UID to agree. The request parser bounds its length and accepts only a canonical, single-line form; accepted nonces are tracked for the service process lifetime.

Linux documents that `SO_PEERCRED` credentials are fixed at `connect(2)`, `listen(2)`, or `socketpair(2)` time, as applicable: [unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html). This implementation authenticates the **connected socket endpoint at connection time**, not every process that may later receive that file descriptor. It does not defend against an authorized process deliberately transferring its connected socket to an untrusted process, an authorized process changing identity after connection, a compromised authorized UID, or an attacker with effective root. Those need additional deployment controls or per-message credentials where appropriate.

The in-memory nonce table rejects duplicate nonces only while this single server process lives. It does not persist across restart or coordinate multiple service instances. The lab tests actual identities and file effects in one disposable Linux guest; it does not establish production deployment, policy coverage for other operations, or CVP eligibility/approval.
